## Channel map

Use this page when the result is ready to share and the only question is where
to say it.

### Internal team chat

Use [`slack-message.md`](slack-message.md).

Best for:

- a lab or platform team that already knows the workflow;
- quick visibility after one useful command-level trial;
- asking whether anyone wants to review the result or try the same swap.

### Direct note to a workflow owner

Use [`email-blurb.md`](email-blurb.md).

Best for:

- one maintainer or platform lead;
- a small decision that needs a little more context than chat;
- situations where you want to point at the exact command, evidence, and next step.

### Workflow or module pull request

Use [`module-pr-note.md`](module-pr-note.md).

Best for:

- a repo where the Picard step already lives;
- a narrowly scoped substitution or optional toggle;
- review conversations that need to stay tied to code and evidence.

### Release notes or changelog

Use [`release-note.md`](release-note.md).

Best for:

- telling existing users that the option exists;
- documenting a command-level change that has already been reviewed;
- keeping the wording short and factual.

### Public community post

Use [`community-post.md`](community-post.md).

Best for:

- a broader audience outside one repo or team;
- communities where readers may not know your workflow details;
- sharing a short result plus a clear first-trial path.

### GitHub discussion or issue thread

Use [`github-discussion.md`](github-discussion.md).

Best for:

- workflow-specific communities already talking about Picard steps;
- maintainers who prefer discussion attached to a repo;
- follow-up where links, evidence, and questions need to stay together.

### Still deciding whether to share

Use [`evaluation-checklist.md`](evaluation-checklist.md) and
[`team-review-template.md`](team-review-template.md) first.

Best for:

- results that still need to be written down cleanly;
- cases where the trial happened but the recommendation is still fuzzy;
- internal review before wider visibility.

### If you need the order

Use [`launch-plan.md`](launch-plan.md).

That file is for sequencing. This file is for choosing the right channel.
