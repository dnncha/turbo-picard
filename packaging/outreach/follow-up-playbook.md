# Follow-up playbook

Use this after the first post or message goes out.

## If someone asks where to start

Point them to:

- `one-page-brief.md`
- `first-pass-bundle.md`
- the command-specific docs or workflow starter that fits their case

## If someone asks whether this replaces all of Picard

Answer narrowly:

- no, the intended path is one command at a time
- the practical question is whether a specific Picard step can be proven on representative data

## If someone asks for proof

Point them to:

- the checked-in benchmark evidence
- the real-data comparison material
- the exact command-level result you are talking about

## If someone seems interested

Next move:

1. ask which Picard command actually hurts in their workflow
2. point them to the first trial path
3. keep the scope on one command

## If the discussion goes quiet

Do one follow-up only:

- restate the command that was tested
- restate the workflow context
- ask whether a narrow trial or repo discussion would be useful
