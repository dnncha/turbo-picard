# Launch plan

Use this when the package is ready to be shown outside a single local test.

Recommended order:

1. Make sure one or two representative command-level trials exist and are easy
   to cite.
2. Share the short internal message or evaluation checklist with the immediate
   workflow team first.
3. Post a concise public note where Picard, workflow, or bioinformatics users
   already pay attention.
4. Point people to the workflow starter bundle instead of only to the repo root.
5. Follow up with the exact command that was tested and the workflow context it
   helped.

Good channels:

- internal lab or platform Slack / chat
- GitHub Discussions or project discussions where pipeline maintainers already look
- module or workflow pull requests where a Picard step is already under discussion
- release notes or changelog updates for pipeline users

What to lead with:

- which Picard command was actually tried
- why that command was chosen
- what workflow shape it fits
- where the starter files and one-command trial live

What not to lead with:

- blanket claims about replacing all of Picard
- synthetic speed numbers without telling people what command they apply to
- toy examples that do not resemble the real workflow context
