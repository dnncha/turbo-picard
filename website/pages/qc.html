Run supported collectors together.

Running a separate process for each QC metric can mean opening, decoding and walking through the same alignment file repeatedly. CollectMultipleMetrics gives you one task for a set of collectors and a shared output prefix.

Turbo Picard implements Picard’s default and explicitly supported program sets, including scoped forwarding of collector-specific options. Its compatible BAM/CRAM multi-program execution paths can share an alignment pass. Not every combination has identical prerequisites or fits the same execution path, so “one command” should not be interpreted as “every conceivable metric in one pass.”

Before changing tools, list the output files the downstream pipeline actually consumes. A report may use insert-size metrics, base-quality distributions or alignment summaries. Avoid requesting expensive outputs merely because they appeared in an old template.

Make the program list explicit.

Picard’s list-style arguments support clearing the default program list before adding the desired programs. Here is a focused pair of collectors, writing to a new results prefix.

Shell example
run_dir="$(mktemp -d)"
TURBO_PICARD_REQUIRE_NATIVE=1 \
  "$HOME/.venvs/turbo-picard/bin/turbo-picard" CollectMultipleMetrics \
  I=/data/sample.bam O="$run_dir/qc" \
  PROGRAM=null \
  PROGRAM=CollectInsertSizeMetrics \
  PROGRAM=QualityScoreDistribution
printf 'QC outputs retained in %s\n' "$run_dir"

For CRAM, add the correct REFERENCE_SEQUENCE. Check a collector’s reference requirement even for BAM: an alignment-summary task with reference-backed mismatch calculations is not necessarily equivalent to a no-reference summary.

Shared I/O must not blur different filters.

Two collectors reading the same BAM can intentionally count different subsets of records. Duplicate handling, secondary/supplementary inclusion, original qualities and read-group accumulation levels change the statistics. Those choices belong to the collector contract, not to a single generic “QC filter.”

The native multi-program implementation has separate record gates and tests for conflicting filters. When adding EXTRA_ARGUMENT forwarding, confirm that both the program and that argument are in the supported scope. An unsupported program or forwarded option belongs on upstream Picard, not in a silently reduced report.

RNA-seq is a different case. CollectRnaSeqMetrics is upstream-only in this release. The presence of other native QC collectors does not imply native RNA-seq metrics support.

Metrics text and PDF summaries are different promises.

The comparison target is supported metrics text and its values. Turbo Picard’s lightweight PDF summaries do not reproduce Picard’s full plotting system. Inspect the visual output separately when the chart itself is part of your deliverable.

Benchmark the exact bundle you use.

The saved small-fixture suite includes CollectMultipleMetrics, but its headline ratio is not a forecast for your whole genome or your program list. Short tasks can be dominated by Java startup. Larger tasks can instead be limited by decompression, storage and the work inside each collector.

Time the complete current QC step and its candidate replacement on the same input and resource allocation. Compare all expected metrics, names, accumulation levels and files. Run the downstream report step too. Then repeat on representative samples rather than extrapolating from a single successful run.
