Coordinate order separates mates. Direct streaming saves a full pass when queryname-ordered.

A coordinate-sorted BAM puts distant mates megabases apart, forcing naive exporters to buffer large fractions of a genome in RAM. Setting TMP_DIR or MAX_RECORDS_IN_RAM in Turbo Picard’s SamToFastq enables a bounded disk-backed queryname stage so resident memory stays predictable.

When the input is already queryname-ordered or exported as a single unpaired stream, PR #76 streams directly in a single pass with parallel BGZF output—measured at 0.577 s vs 0.988 s on prior main (1.71x faster, and 1.92x faster than Picard 3.4.0 at 1.109 s on 600k paired BAM reads on Apple M5).

For CRAM inputs, pass REFERENCE_SEQUENCE explicitly.

A paired-export example with explicit temporary storage.

Shell example
run_dir="$(mktemp -d)"
mkdir "$run_dir/scratch"
TURBO_PICARD_REQUIRE_NATIVE=1 \
  turbo-picard SamToFastq \
  I=/data/coordinate-sorted.bam \
  F="$run_dir/reads_R1.fastq.gz" \
  F2="$run_dir/reads_R2.fastq.gz" \
  TMP_DIR="$run_dir/scratch" MAX_RECORDS_IN_RAM=100000
printf 'FASTQs retained in %s\n' "$run_dir"

Preserve Picard orientation, clipping, and filters.

Turbo Picard matches Picard’s RE_REVERSE orientation restoration, hard-clipping/OQ restoration rules, secondary/supplementary/vendor-fail filters, UNPAIRED_FASTQ, and OUTPUT_PER_RG split outputs. Compare sequences, names, and quality strings rather than compressed gzip bytes.

When this is the right exporter.

Use Turbo Picard when an existing pipeline relies on Picard’s F/F2/OUTPUT_PER_RG flags and exact read filtering. Keep upstream Picard for unsupported exotic flag combinations via fallback.
