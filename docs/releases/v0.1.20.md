# Turbo Picard v0.1.20

This release adds native `CollectRnaSeqMetrics` and `CollectSamErrorMetrics`,
runs the QC collectors in parallel on indexed BAM input, and speeds up sorting,
`MarkDuplicates` and `CollectGcBiasMetrics` setup. It is also the first release
since 0.1.18 on PyPI: the 0.1.19 upload did not complete.

## New native commands

- `CollectRnaSeqMetrics` on coordinate-sorted BAM and CRAM with a UCSC refFlat
  file: core RNA-seq metrics, per-sample, library and read-group levels,
  ribosomal intervals, strand specificity and the normalized coverage
  histogram.
- `CollectSamErrorMetrics` on reference-backed, coordinate-sorted BAM and CRAM:
  the error, indel-error and overlapping-read calculators across Picard's 26
  default stratifiers, with `ERROR_METRICS`, `INTERVALS`, `MAX_LOCI`,
  `PRIOR_Q`, `LONG_HOMOPOLYMER` and `FILE_EXTENSION`.
- Options outside that scope, such as text SAM input or VCF known-variant
  filtering, still go to upstream Picard. Native coverage is now 35 Picard
  commands plus 6 Turbo Picard utilities; 86 commands are delegated.

## Performance

- QC collectors read indexed BAM input per contig on several threads.
- `CollectGcBiasMetrics` setup on chr20 of HG02675 (8-core VM) went from 98 s
  to 25.5 s, and the 7-program `CollectMultipleMetrics` bundle from 153 s to
  90 s, with byte-identical output.
- External sorting, `SortSam`, `MergeSamFiles`, `SamToFastq` and bounded
  `MarkDuplicates` were reworked. On one Apple M5 host PR #76 reported
  `MarkDuplicates` on 1.2M paired reads at 0.303 s against 0.627 s before, and
  `SortSam` coordinate at 0.520 s against 1.223 s.
- Region workers and `CollectMultipleMetrics` collectors scale to every core.

## Parity checks

- Metrics must now equal Picard's at printed precision. The comparator
  previously accepted differences up to 1e-5.
- The parity gate passes against Picard 3.4.0 on this release's commit,
  including the two new commands.

## Known issues

- At 8 cores on a 4x genome, FastDup runs `MarkDuplicates` in 185 s and
  turbo-picard in 270 s, using 231 MiB against FastDup's 3.8 GiB. Tracked in
  #9.
