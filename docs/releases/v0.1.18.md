# Turbo Picard v0.1.18

This release makes turbo-picard usable by coding agents. It adds an MCP server,
reports whether Java fallback is ready to run, and ships an agent kit for Claude
Code, Codex and Cursor. It also fixes a MarkDuplicates tie-break so tied
representatives match Picard 3.4.0.

## Agent integration

- `turbo-picard mcp` runs a Model Context Protocol server on stdio, with
  `capabilities`, `explain`, `trial`, `doctor` and `run` tools. The report tools
  return the existing JSON contracts. `run` executes without a shell and
  refuses outputs that name an input or an existing file unless `overwrite` is
  set. Register it with `claude mcp add turbo-picard -- turbo-picard mcp` or
  `codex mcp add turbo-picard -- turbo-picard mcp`.
- `doctor` prints `fallback_ready`, `fallback_status` and, when delegation is
  unavailable, a `fallback_hint` install command. `explain --json` adds
  `fallback_ready`, `fallback_status` and `fallback_install_hint`.
- `packaging/agents/` holds a Claude Code skill and plugin, a Codex `AGENTS.md`
  snippet and a Cursor rule. Each tells the agent to run `explain --json` first.
- The `turbo-picard-full` Bioconda recipe pins turbo-picard, upstream Picard
  3.4.0 and OpenJDK so one environment covers every Picard 3.4.0 command name.

In the agent-selection eval (Claude Sonnet 5.5, ten Picard-shaped prompts, two
runs each), the agent chose turbo-picard in 0/20 baseline runs and 18/20 runs
with the skill and MCP server installed.

## Correctness fix

- MarkDuplicates breaks equal-score ties on the tile, x and y parsed from the
  read name before file order, as Picard 3.4.0 does. Before this fix, 8 of 6,900
  reads in the eval's MarkDuplicates task kept a different representative from
  Picard while metrics matched. The `pair-score-tie-reverse-r1` fixture pins
  Picard 3.4.0 output.

## Engineering

- The single-pass metrics pipeline evaluates only the gate families of active
  collectors.
- Paired fragment entries pass through a 4 MiB bloom filter. A synthetic
  native-path mix of 400,000 pairs moved from 1.22 s / 198.0 MB to
  0.79 s / 125.2 MB with identical BAM and metrics hashes. This is not a Picard
  comparison or a WGS guarantee.
- `tools/parity_gate.sh` runs every command-matrix parity script, including the
  new MCP check.
