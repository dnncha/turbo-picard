# Turbo Picard v0.1.17

This patch release repairs scientific correctness across duplicate marking,
metrics, sorting, validation, mate repair, and VCF processing. It also makes
native parity checks stricter so Java fallback or incomplete comparisons cannot
hide native failures.

## Correctness fixes

- Share duplicate selection across SAM, BAM, and CRAM, retain the best-quality
  representative, and detect fragment duplicates against paired endpoints.
- Validate every input sequence dictionary, including conflicting supplied MD5
  checksums, before duplicate planning or output creation. Preserve colliding
  read-group definitions by renaming IDs and rewriting the affected records.
- Count sequence yield independently of quality availability. Missing BAM
  qualities no longer become Phred 255 in quality consumers.
- Preserve paired and unpaired alignment metric rows and histograms together,
  and account for PF noise reads in standalone and combined collectors.
- Check actual sort order before skipping sorting, and use shared Picard tie
  rules across SAM, BAM, and spill paths.
- Use supplied references in SAM summary validation, detect common structural
  errors, and preserve Picard's exact clean/warning/mixed/error exit categories.
- Repair primary and supplementary mate groups natively, including missing
  primaries, secondary records, mapped/unmapped mates, and tandem insert sizes.
- Merge VCF field definitions across inputs and reject invalid gather ordering,
  overlapping shard boundaries, or undefined fields before opening the output.
- Reuse CollectHsMetrics interval lookups within alignment blocks, including
  off-target gaps, while preserving metrics and coverage outputs.

## Verification changes

New `markduplicates-v2` comparisons protect all mandatory SAM fields, typed
tags except PG, scientific sequence/read-group metadata, record multiplicity,
complete metrics, and histograms. Independent mutation tests require corrupted
fields to fail. Documented provenance and representation normalizations remain
explicit; historical benchmark evidence retains its original comparison label
and measurements.

CI runs the complete parity workload list and live adversarial cases against
Picard 3.4.0 and 3.5.0. Workload runs require native execution. BAM fixtures use
identical arguments for the selected live Picard version and the native command,
and validation exit codes must match exactly. Failed adversarial runs retain
commands, outputs, exit statuses, versions, and hashes.

Publication follows successful CI on the exact main commit. Validation covers
the Rust and Python suites, scientific parity, package/container checks,
workflow-starter execution, release metadata, and strict documentation builds.
Platform-specific wheel builds and install smoke checks run before upload.

These fixes do not add production-cohort or performance claims. Existing
benchmark timings remain measurements of their recorded inputs and contracts.
See [What Parity Means](https://turbo-picard.readthedocs.io/en/latest/parity.html)
for supported scope and evidence boundaries.
