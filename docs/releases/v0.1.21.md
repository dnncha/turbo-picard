# Turbo Picard v0.1.21

This release delivers genome-scale `MarkDuplicates` parity against Picard 3.4.0
on a 30x GRCh38 whole genome (740M reads), adds GATK4 `--kebab-case` and bare
boolean flag parsing plus an isolated MCP `verify` tool for coding agents, and
hardens non-coordinate `MarkDuplicates` memory handling.

## Genome-scale parity and 30x WGS evidence

- **Optical duplicate parity at genome scale (#87).** Matches Picard's signed
  16-bit Java `short` tile coordinate wrap and FR/RF split within mixed-orientation
  duplicate sets. On 1000 Genomes HG02675 (`ERR3242389`, 740,367,510 records),
  `MarkDuplicates` now matches Picard 3.4.0 exactly in metrics, duplicate count
  (79,289,617), and SAM columns 1-11 MD5 while running 3.6x faster (59m 01s vs
  3h 30m 07s on Host A, 8 vCPU) with 97x less RAM (355 MB vs 34.4 GB).
- **`@PG` chaining and `PG` tags (#88).** Chains `@PG` IDs and writes record
  `PG` tags matching Picard when input headers already contain `MarkDuplicates`.
  On chr21 of HG02675 (11,405,002 records), `DT`, `DS`, `DI`, and `PG` tags
  matched Picard with zero differences.
- **30x WGS `CollectWgsMetrics` comparison (#89).** On the same 30x GRCh38 BAM,
  `CollectWgsMetrics` ran in 5m 08s at 352 MB RSS vs Picard 3.4.0's 2h 13m 55s
  at 4.0 GB RSS (26x faster, 11x less memory), matching every metric field and
  histogram row. Full log in `benchmarks/wgs-30x-colab-2026-11-23/README.md`.
- **Oversized non-coordinate `MarkDuplicates` guard (#94, #103).** Refuses
  oversized non-coordinate inputs up front and delegates to upstream Picard
  instead of exhausting memory in the in-memory path.

## GATK4 syntax and agent integration

- **GATK4 CLI flag normalization (#93, #95).** Accepts `--kebab-case` option
  names (such as `--create-index`, `--metrics-file`, `--sort-order`) and bare
  boolean flags (such as `--remove-duplicates`, `--assume-sorted`, `-AS`) across
  the canonical Picard option table.
- **Isolated MCP `verify` tool (#95).** `turbo-picard mcp` now exposes a sixth
  tool, `verify`, that redirects outputs to a fresh temporary directory, runs
  native `turbo-picard` and upstream Picard side by side on read-only inputs,
  and compares BAM/SAM/metrics/text outputs structurally.
- **Hardened MCP output guards and widened agent kits (#93).** Unified declared
  input/output parsing across `agent_contract` and `mcp`, fixed case-insensitive
  input-overwrite detection, updated Claude Code, Codex, and Cursor kits, and
  added WGS, GATK4, and shim scenarios to `benchmarks/agent-selection/`.

## Architecture and site updates

- **Deepened CLI and `markdup` modules (#96, #97, #98, #99).** Unified indexed
  BAM/CRAM discovery in `bam_parallel`, extracted `reference_cache`,
  `command_catalog`, `validate_sam`, and `vcf` (unifying `SortVcf`/`MergeVcfs`),
  and isolated the `turbo-picard-markdup` external-spill binary wire codec in
  `codec.rs`.
- **Website `/evidence/` overhaul and brand mark (#92).** Replaced the mascot
  mark with a geometric aligned-reads chevron and added the 30x GRCh38 proof
  ledger on `/evidence/`.

## Known trade-offs

- On the 30x GRCh38 BAM, `MarkDuplicates` used 99.2 GB peak temporary disk vs
  Picard's 23.3 GB (4.3x more temp disk). Tracked in #86.
- At equal cores (8) on a 4x genome, FastDup finishes `MarkDuplicates` in 185 s
  and `turbo-picard` in 270 s (231 MiB vs FastDup's 3.8 GiB). Tracked in #9.
