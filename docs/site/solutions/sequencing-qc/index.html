Sequencing QC without the repeated work

Run CollectWgsMetrics across parallel 4 Mb regions and bundle CollectMultipleMetrics collectors into one single-pass BAM/CRAM scan—faster and leaner than both Picard and Riker while keeping Picard-identical metrics.

Whole-genome QC vs Picard 3.5.0 and Riker 0.5.0.

On real 1000 Genomes HG02675 GRCh38 alignments (Intel i7-8700, 6 threads, cold page cache), Turbo Picard’s regional CollectWgsMetrics engine matched every metric field and histogram row of Picard 3.5.0:

On 4x WGS, Turbo Picard was ~46x faster and used 11.7x less RAM than Picard 3.5.0, while beating riker wgs by 1.3x in wall time and 4.0x in RAM. On 30x WGS before PR #76, a single capped locus triggered single-threaded whole-contig fallback; PR #76 replaced that fallback with targeted capped-cluster reprocessing (awaiting an i7-8700 rerun).

Run supported collectors together without re-reading the BAM.

Running separate QC commands opens and decompresses the same alignment file multiple times. CollectMultipleMetrics executes compatible collectors in a single HTSlib scan with an asynchronous pipeline reader (scaling up to 6 collector workers by default) that only evaluates predicates required by the selected programs.

Before switching tools, list the output files downstream tasks actually read—skipping unused collectors saves both decode work and disk I/O.

Make the program list explicit.

Picard’s list-style arguments support clearing the default program list before adding desired programs. Here is a native run with explicit output separation:

Shell example
run_dir="$(mktemp -d)"
TURBO_PICARD_REQUIRE_NATIVE=1 \
  turbo-picard CollectMultipleMetrics \
  I=/data/sample.bam O="$run_dir/qc" \
  PROGRAM=null \
  PROGRAM=CollectInsertSizeMetrics \
  PROGRAM=QualityScoreDistribution
printf 'QC outputs retained in %s\n' "$run_dir"

For CRAM, pass REFERENCE_SEQUENCE. Tune region or multi-metric parallelism with TURBO_PICARD_REGION_WORKERS and TURBO_PICARD_CMM_THREADS when needed.

Shared I/O preserves exact per-collector filters.

Different collectors intentionally filter duplicate, secondary, supplementary, and base-quality records differently. The shared native pass compiles each collector’s filter predicates explicitly at startup so combining collectors never blurs their counts. Check EXTRA_ARGUMENT scope before forwarding specialized flags.

RNA-seq note: CollectRnaSeqMetrics remains upstream-Picard only in this release. See Compare tools if greenfield RNA-seq QC is your main need.

Metrics text and PDF summaries.

Supported metrics tables and histograms match Picard. Chart PDFs are lightweight vector/text summaries rather than full R plots.
