Built for people who already know Picard.

The point is not to invent a new workflow language. The point is to keep Picard-style command lines familiar, speed up the commands that matter, and leave unsupported work with upstream Picard when needed.

Familiar command shape

The optional shim installs a picard command for existing workflow managers. Native commands accept Picard-style KEY=VALUE arguments and common aliases.

Parity scripts in CI

Command-specific scripts compare turbo-picard output against Picard for stable records, metrics, sidecars, sort orders, and failure behavior.

Real-data comparison runs

A separate comparator runs Picard and turbo-picard on public or lab BAMs, then writes JSON and Markdown reports with input SHA-256, versions, output digests, file paths, citation fields, and wall times.

Fallback without masking native errors

Unsupported commands can delegate to upstream Picard. Native I/O and malformed native inputs still fail directly, so real errors remain visible.

Know quickly whether it is worth your time.

The package is worth evaluating when Picard is a real bottleneck and you can switch one command at a time. It is not worth forcing into a workflow that needs an instant full-suite replacement.

Good fit

You already run Picard, one or two steps clearly hurt, the workflow boundary is stable, and you can compare outputs on representative data before changing anything wider.

Not a fit yet

You need every Picard command immediately, cannot do side-by-side checks, or the workflow depends on exact Picard-rendered plot PDFs rather than metrics text.

Real data, pinned and repeatable.

Synthetic cases are useful, but they are not enough for a tool people might place in front of large biological studies. The checked-in public runs use fixtures from HTSlib, Picard itself, and GATK's NA12878 mitochondrial test data. Each input is pinned to a source commit and verified by SHA-256, so the saved parity evidence can be rerun instead of taken on trust. GitHub-hosted public inputs must use a /blob/<commit>/ URL and the full 40-character Git commit SHA, not a branch name or short hash. For a scientific release, this is evidence for the tested commands, not proof for every dataset a lab might process. The release checks require enough pinned input data that one tiny fixture cannot carry the claim.

Change one command at a time.

turbo-picard is for pipeline owners who want speed without mystery behavior. Start by running turbo-picard beside Picard, compare stable output, then let fallback handle commands that are not native yet.

1. CompareRun turbo-picard beside Picard on representative inputs.
2. CheckKeep the output comparisons, timings, and benchmark logs.
3. SwitchUse the shim only where the command is covered, with fallback still available.

Current boundaries.

turbo-picard is not a full Picard suite yet. Supported commands are documented one by one, and fallback is still part of the product for workflows that need more.

Metrics before plots

Metrics text is the native parity target. Chart outputs are lightweight PDF summaries, so workflows that require Picard-equivalent rendered plots should use upstream Picard through fallback.

Bioconda path

Release v0.1.9 is prepared for Bioconda submission as turbo-picard plus the optional turbo-picard-picard-shim. The main package keeps the turbo-picard command separate; the shim installs picard only for environments that want that command name. Release checks include python3 tools/bioconda_release_preflight.py and bioconda-utils lint recipes config.yml --packages turbo-picard turbo-picard-picard-shim.

Shim deliberately

The main package keeps the turbo-picard command separate. The optional shim owns picard and should be installed only when that command-name shadowing is intended.

Cite software and data separately

The software citation lives in CITATION.cff. Cite the archived turbo-picard release you used, then cite benchmark and validation inputs separately with immutable source URLs, commits or accessions, and input SHA-256 hashes. That keeps the tool citation distinct from the evidence used to justify a workflow switch.
