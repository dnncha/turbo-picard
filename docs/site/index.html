Built for cautious replacement, not wishful migration.

turbo-picard keeps the Picard command surface familiar while making unsupported areas explicit and delegable through a fallback command.

Drop-in command shape

The optional shim installs a `picard` command for workflow managers. Native commands accept Picard-style `KEY=VALUE` arguments and common aliases.

Parity scripts in CI

Command-specific scripts compare turbo-picard output against Picard for stable records, metrics, sidecars, sort orders, and failure behavior.

Fallback without masking native errors

Unsupported commands can delegate to upstream Picard. Native I/O and malformed native inputs still fail directly, so real errors remain visible. 

cargo install --locked --path crates/turbo-picard-cli --bin turbo-picard --bin picard

export TURBO_PICARD_FALLBACK_COMMAND='mamba run -p /opt/conda/envs/picard picard'

picard SortSam I=input.bam O=coordinate.bam SORT_ORDER=coordinate
picard RevertSam I=aligned.bam O=unmapped.bam
picard SetNmMdAndUqTags I=coordinate.bam O=tagged.bam R=reference.fa

The replacement path is evidence-first.

turbo-picard is designed for pipeline owners who need speed without accepting mystery behavior. Start by shadow-running native commands, compare stable output against Picard, then let the fallback command keep unsupported surfaces boring.

1. ShadowRun native commands beside Picard on representative pipeline shards.
2. ProveUse parity scripts and benchmark logs as release-gate evidence.
3. SwitchEnable the shim where the native surface is covered, with fallback still available.
