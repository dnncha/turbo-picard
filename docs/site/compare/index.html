Keep an existing Picard task easy to evaluate.

Turbo Picard implements selected commands in Rust with familiar names and KEY=VALUE arguments. Start where the workflow already has a costly Picard step and specific outputs to preserve. Check its native scope, then run both implementations with separate outputs.

Compare records, flags, metrics, histograms and sidecars as required by the next task. Native coverage is command- and option-specific. Lightweight metric PDFs do not reproduce Picard's full rendered charts. Configured or detected upstream fallback is a distinct execution path; use native-only mode when evaluating native performance.

Keeping Picard can be the best decision when required behaviour lies outside that scope, validation is incomplete or the measured improvement does not justify the change.

Specialists can improve a different workflow boundary.

samtools and Sambamba

samtools markdup expects coordinate-sorted records carrying the mate information from fixmate -m. Include required preparation when it is missing. If the workflow already produces it, avoid charging for it again. Sambamba offers parallel alignment processing through its own interface. Compare each tool's exact current options rather than assuming every duplicate-marking mode is interchangeable.

FastDup

FastDup advertises Picard-compatible results and detailed metrics, while documenting that sorting stability can change which representative is retained. Identifying the same duplicate families and emitting the same marked records are separate comparison targets. Review whichever contract the workflow actually needs.

Riker

Riker deliberately uses a different QC interface and output model. Its documentation includes bundled single-pass collection, RNA-seq metrics, plots and intentional metric changes. Its authors publish benchmarks on WGS, exome and RNA-seq inputs. Those are reasons to evaluate it for a new QC flow; Turbo Picard's small direct smoke comparisons do not establish a large-scale speed advantage.

Streaming duplicate marking

SAMBLASTER and dupblaster fit query-grouped aligner output before coordinate sorting. dupblaster also documents library awareness and a sequencing-duplicate model based on tile identity. These are different input and scientific contracts from every Picard mode. Evaluate the complete stream and its outputs when a workflow redesign is acceptable.

UMI processing and sorting

fgumi covers UMI extraction, correction, grouping and consensus alongside preprocessing tools. Turbo Picard's explicit barcode-tag grouping is a narrower capability. mako provides a focused sorter with several orders, external merging and verification. Include these alternatives when choosing a UMI or sorting workflow.

Decide what must agree before comparing speed.

Record the same biological input, reference, versions, exact arguments, required preparation and final outputs. Match filtering, optical handling, barcode policy, sort order, compression and available resources. Measure wall time, CPU time, process RSS, scratch and output validity. Preserve failed and slower runs.

A different representative or metric definition is a contract difference. Assess the downstream effect separately before treating it as a scientific regression. The v0.1.16 release notes retain native competitors that were faster on a paired synthetic fixture; Turbo Picard does not claim to lead every workload.
