Prove the switch on your data.

A reproducible comparison is more convincing than a headline speedup. Generate a script for one representative task, then run it on your own infrastructure.

From an input file to an inspectable trial.

The script creates a fresh directory, installs a pinned wheel in an isolated environment and checks out the matching evaluation tools. It runs Turbo Picard and Picard with separate outputs. It does not overwrite previous evidence or use Java fallback for the native side.

Prerequisites: Python 3.11 or newer with venv, Git, samtools, and a Java runtime suitable for your upstream Picard jar. Use Picard 3.4.0 to match the project’s reference. Network access is needed for the pinned source checkout and wheel installation—not for uploading your input.

Choose a representative task

Runs entirely in your browser. No upload, no saved paths, no command execution.

Static example · MarkDuplicates / BAM
#!/usr/bin/env bash
set -euo pipefail
# Review paths and fixed trial options before execution. No input is uploaded.
# Set TMPDIR to suitable scratch storage before running, if needed.
python3 -c 'import sys; assert sys.version_info >= (3, 11), "Python 3.11+ required"'
for tool in git java samtools; do command -v "$tool" >/dev/null; done
work="$(mktemp -d)"
printf 'Trial directory: %s\n' "$work"
python3 -m venv "$work/venv"
"$work/venv/bin/python" -m pip install --only-binary=:all: 'turbo-picard==0.1.13'
git clone --depth 1 --branch 'v0.1.13' \
  https://github.com/dnncha/turbo-picard.git "$work/source"
turbo_prefix="$("$work/venv/bin/python" -c 'import shlex,sys; from pathlib import Path; print(shlex.quote(str(Path(sys.executable).with_name("turbo-picard"))))')"
"$work/venv/bin/python" "$work/source/tools/compare_real_data.py" \
  --skip-build --commands MarkDuplicates \
  --input-bam '/data/sample.bam' \
  --picard-command 'java -jar '"'"'/opt/picard/picard.jar'"'"'' \
  --turbo-picard-command "$turbo_prefix" \
  --output-dir "$work/results" \
  --shareable-report "$work/results/shareable.md"
printf 'Evidence retained in %s/results\n' "$work"
# Compare status, scientific outputs and your downstream consumer.
# One timing per side is not a repeat-run benchmark. Failed runs are retained.

The example uses placeholder paths. Review the complete script before running it. It is a plan, not an input-validation result.

Read the comparison, not just the clock.

The runner writes real-data-comparison.json and a Markdown report, plus intermediates in its work directory. Look for command status, both exit codes where reported, the comparison rule, digests, artifact paths and timing. A failed or unsupported comparison is not a speed result.

The runner uses command-specific comparisons. It does not assert that compressed files are byte-for-byte identical or that every possible downstream behaviour has been tested. Review the comparison contract, inspect requested sidecars and run your downstream consumer before adoption.

The default runner records one timed invocation per side, not a statistically robust benchmark. For a performance decision, repeat with fresh directories and comparable resource allocations. Record compression settings, thread counts, storage, input characteristics and peak process memory separately; do not infer peak memory from a successful run.

Make the test match the workflow.

The builder is deliberately limited to fixed supported trial tasks. For MarkDuplicates, add permitted --markduplicates-arg KEY=VALUE arguments to match your workflow after checking their scope. Input, output and metrics paths belong to the runner. Other advanced configurations may need a carefully constructed manual comparison rather than this starter.

Test representative read groups, libraries, duplicate families, input orders and formats. A mitochondrion or a synthetic BAM cannot stand in for every whole-genome cohort. Once the required outputs agree and the measured trade-off is worthwhile, pin the chosen executable and change only that task.

Evidence stays under your control.

The interactive builder sends no form fields to a server and stores no paths in URLs or browser storage. Copying or running the generated script is your action. The hosted documentation service may provide its own site infrastructure and analytics; that is separate from this local planner.

The runner’s shareable.md summary omits local paths, input hashes, raw arguments and raw data. Review it before posting. Full reports and intermediate files can contain sensitive details; do not attach them publicly by default. Failed runs are retained for investigation. Cleanup is an explicit separate decision.
