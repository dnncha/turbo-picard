Historical small-fixture evidence, not a release forecast.

The saved suite dated 2026-08-14 records 32/32 PASS across 32 commands. These are developer-run, small-fixture comparisons against Picard. They predate v0.1.13 and were not rerun merely because the website changed.

The saved summary is a 84.52x geometric mean, 99.51x median, a 22.88x floor on SetNmMdAndUqTags, and a 272.12x maximum on NormalizeFasta. Large ratios on short commands can largely reflect JVM startup. They should not be projected onto a whole-genome task or used as a universal competitor ranking.

Absolute medians are shown below. “Saved ratio” preserves the suite’s recorded median of run-level speed ratios; it need not equal the ratio of the two displayed medians. Generator inputs are the original script parameters, not an independently verified count of records in every produced file.

What is missing: an independently reproduced, representative full-scale comparison proving production-wide speed or memory gains. The native sorter improvement in v0.1.13 has tests, not a new whole-pipeline speed claim. The separately measured 77.92% memory reduction concerns a Python comparison helper on one million synthetic SAM records—not MarkDuplicates RSS.

Parity has a defined scope.

The synthetic suite checks selected commands, options and fixtures. Separate pinned public real-data evidence covers a 12-command release set on the documented small inputs, including mitochondrial BAM/CRAM and variant fixtures. This is not a substitute for varied full-scale sequencing data or downstream validation in your pipeline.

Read the comparison contract for each command. Metrics text is a target for supported collectors; lightweight PDF summaries are not a reproduction of Picard’s charts. Compressed-file bytes and program-header differences require deliberate comparison rules, not a blanket “identical” claim.

Saved benchmark exceptions

AccelerationStatus, capabilities, doctor, explain and trial are utility or inspection commands, not timed upstream data-processing replacements. CollectHsMetrics has separate parity checks; a public performance benchmark awaits representative capture data.

Turbo Picard is not a full Picard suite. Unsupported commands and options require upstream Picard when fallback is configured. Switch only the commands where the evidence supports the change.

Pinned public-input evidence

A scientific release needs a documented comparison portfolio, not one tiny fixture and not proof for every dataset. The current 12-command release set spans the designated release_candidate inputs. Record the full 40-character Git commit SHA and the input SHA-256 when citing or reproducing a case.

To add new evidence, use python3 tools/compare_real_data.py with the required input and fresh output arguments described in the evaluation guide. Review its /evidence/manifest-entry.json artifact before using python3 tools/update_real_data_manifest.py. Then run python3 tools/verify_real_data_evidence.py and the --release-ready variant. A manifest-entry.json file alone is not a passing comparison or a release approval.

Reproduce the checks and cite the correct thing.

Repository checks tie public claims to logs, coverage and release evidence:

Evidence verification · repository checkout
python3 tools/verify_benchmark_log_evidence.py
python3 tools/verify_benchmark_suite_coverage.py
python3 tools/verify_benchmark_thresholds.py
python3 tools/verify_real_data_evidence.py --release-ready

The fixture-suite release thresholds are 5.00x floor, 20.00x geometric mean and 50.00x maximum. These are internal saved-suite gates, not promised speedups for other inputs.

For the software citation, consult CITATION.cff and cite the archived turbo-picard release you used. Cite benchmark inputs separately, preserving the accession or source revision and input SHA-256. Do not attach a historical archival DOI to a newer release it does not identify.

Bioconda distribution status and maintainer checks

The v0.1.13 software is released on PyPI and GHCR. Bioconda acceptance remains pending as of 6 September 2026. A recipe submission is not proof of channel availability. Release preparation and upstream lint are distinct checks:

Distribution checks · appropriate repository checkout
python3 tools/bioconda_release_preflight.py
bioconda-utils lint recipes config.yml --packages turbo-picard turbo-picard-picard-shim

Do not interpret a preparation-only recipe or an unchecked archive checksum as a completed channel release.
