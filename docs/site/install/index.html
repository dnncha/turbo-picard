Install from PyPI, without shadowing upstream Picard.

The PyPI distribution includes both turbo-picard and a picard compatibility shim. An isolated environment and an explicit path keep your original Picard command intact. This example does not activate the environment or change your PATH.

Isolated install · Linux / macOS
python3 -m venv "$HOME/.venvs/turbo-picard"
"$HOME/.venvs/turbo-picard/bin/python" -m pip install \
  --only-binary=:all: "turbo-picard==0.1.13"
"$HOME/.venvs/turbo-picard/bin/turbo-picard" --version

--only-binary=:all: deliberately requires a wheel instead of silently starting a native source build. If no wheel matches the platform, check the supported platforms or use the documented source-build requirements. A source build needs a Rust toolchain and native prerequisites; a matching wheel does not.

For a completely separate evaluation, use a new virtual-environment directory rather than upgrading an existing one used by a pipeline. Once a task is validated, pin its version in the workflow environment or container.

Use the versioned container.

The published container provides the CLI without installing it into your host Python environment. Verify the version before using it.

Versioned container
docker run --rm ghcr.io/dnncha/turbo-picard:0.1.13 --version

For real work, mount your inputs read-only, provide a separate writable output/scratch location and match permissions to your execution environment. Paths inside the command must refer to those container mounts. The versioned reference image is not a promise of a native ARM64 container; inspect its manifest before choosing a host.

Check what will actually run.

Inspect the installed executable
"$HOME/.venvs/turbo-picard/bin/turbo-picard" doctor
"$HOME/.venvs/turbo-picard/bin/turbo-picard" capabilities --json \
  --command MarkDuplicates

doctor reports runtime and fallback state. Command discovery reports the documented scope, not a completed validation of your input file or every option. To prohibit Java fallback during an evaluation, set TURBO_PICARD_REQUIRE_NATIVE=1 for the native run.

Native paths need no JVM and no AI model or service. A side-by-side comparison still needs the upstream Picard/JVM runtime as the reference. Use an explicit Picard jar or executable rather than accidentally comparing Turbo Picard with its own picard shim.
